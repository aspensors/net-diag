# net-diag

`net-diag` — диагностическая утилита Python 3.10+ для наблюдения за проблемами доступа к домену на уровнях DNS, TCP, TLS/SNI и HTTPS. Она не изменяет настройки сети и не пытается обходить ограничения: результат — воспроизводимый отчёт для пользователя, владельца сервиса или сетевого администратора.

## Возможности

```text
домен
  ├─ System DNS (socket.getaddrinfo) ─┐
  ├─ Cloudflare DoH + Google DoH ─────┼─ сравнение IP-адресов
  ├─ TCP connect :443 (опция :80) ───┼─ RTT / reset / timeout / unreachable
  ├─ TLS ClientHello с SNI и без SNI ┼─ транспортное сравнение
  └─ HTTPS HEAD/GET ─────────────────┴─ HTTP-код / Location / Server
                                             ↓
                                          verdict + рекомендации
```

- Изолированное ядро `core/`: только стандартная библиотека и `httpx`, без GUI/Rich.
- CLI с live-этапами, цветными статусами и JSON-экспортом.
- Тёмный CustomTkinter GUI: список доменов, журнал по мере проверки, вердикт, экспорт JSON.
- Ограниченные таймауты и нормализованные ошибки вместо необработанных стектрейсов.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

На Linux для Tk может потребоваться пакет вашей ОС `python3-tk`.

## Запуск

```bash
# GUI — режим по умолчанию
python main.py

# один домен
python main.py example.com

# несколько доменов, таймаут 10 секунд, JSON-отчёт
python main.py example.com example.org --timeout 10 --json report.json

# файл, одна запись на строку; строки с # — комментарии
python main.py --file domains.txt --port-80

# принудительный GUI, даже если переданы другие параметры
python main.py --gui
```

Пример консоли:

```text
──────────────── example.com ────────────────
OK      DNS (system): 93.184.216.34 (12 ms)
OK      DNS (DoH): 93.184.216.34 (241 ms)
OK      TCP: Успешных handshake: 1/1. (34 ms)
OK      TLS/SNI: TLS с SNI: 1/1 успешно; контроль без SNI: 1/1. (122 ms)
OK      HTTP: HTTPS HTTP 200. (143 ms)
OK      Verdict: OK: Clean: Проверенные ...
```

GUI содержит поле ввода и кнопки `Загрузить файл` / `Запустить` вверху, потоковый журнал этапов в центре, итоговый вердикт и `Экспорт JSON` снизу. Проверка выполняется в фоновом потоке; UI не блокируется.

## Матрица вердиктов

| Вердикт | Наблюдаемое условие | Рекомендация |
|---|---|---|
| `OK: Clean` | TLS/SNI или HTTPS проходит, явных признаков нет | Сохранить базовый отчёт |
| `DNS Poisoning Detected` | DNS-ответы различаются **и** TLS с адресов system DNS не проходит, при успешном TLS по адресам DoH; либо system DNS выдал только непубличные адреса | Сверить зону, использовать доверенный DNS по политике сети |
| `IP Blacklist / TCP Drop` | Все TCP/443-пробы завершились timeout/reset/unreachable | Проверить маршрут, firewall и ACL с администратором |
| `DPI SNI Block` | TCP есть, TLS с целевым SNI не проходит, контроль без SNI проходит | Исключить проблему сервера/TLS, передать данные владельцу сети |
| `HTTP Hijack / Redirect Block` | Редирект/Server содержит маркеры промежуточной страницы | Проверить заголовки, сертификат и сравнить другую сеть |
| `Inconclusive` | Недостаточно успешных проб | Повторить позднее или из другой сети |

Это эвристики, а не доказательство типа оборудования или действий провайдера. Разные ответы DNS сами по себе не считаются подменой: CDN, GeoDNS, split-horizon DNS, captive portal, IPv6-маршрутизация и политика самого сайта могут создавать похожие признаки. TLS-контроль сознательно отключает проверку сертификата **только** для изоляции эффекта SNI; прикладная HTTPS-проба использует стандартную проверку сертификата.

## Структура

```text
net-diag/
├── core/
│   ├── models.py       # dataclass-модели и перечисления
│   ├── checker.py      # DNS / DoH / TCP / TLS / HTTP пробы
│   └── analyzer.py     # вердикты и рекомендации
├── cli/app.py          # argparse + Rich
├── gui/app.py          # CustomTkinter + рабочий поток
├── main.py             # выбор GUI/CLI
└── requirements.txt
```

## Ограничения и эксплуатация

Проверяйте только домены и сети, для диагностики которых у вас есть разрешение. DoH-провайдеры должны быть доступны из вашей сети; их недоступность не считается доказательством фильтрации. HTTP-проба намеренно не следует редиректам, чтобы сохранить первичный `Location` для отчёта. JSON включает этапы, ошибки, тайминги и заголовки ответа — перед передачей третьим лицам проверьте его на чувствительные данные.
